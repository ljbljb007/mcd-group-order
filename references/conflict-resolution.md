# 冲突消解与异议收敛

## 1. 为什么用「提案先行 + 异议收敛」

逐个问"你想吃什么"在多人场景下必然失败：

- 6 个人 × 3 轮 = 18 次往返，还没开始点就已经累了
- 每个人给的答案互相冲突，最后还是要有人做裁决
- 先问偏好会拉高期待，后续预算砍掉任何一样都会不满

改成先给方案再收异议：

- 提案成为**讨论基准**，异议是"相对于方案的偏差"，认知负担极低
- 没意见的人自动通过，**静默即同意**，不需要等待
- 裁决权天然落在发起人身上，AI 只负责给出代价（+¥X / −¥X）

话术模板：

```
🍔 首版提案（6人 · ¥150）
个人池：巨无霸×3 / 麦香鱼×2 / 板烧鸡腿堡×1 + 可乐×6
共享池：大薯×2 / 麦乐鸡(5块)×3
硬约束：不吃辣 ✓ | 控热量 2人 ✓（已单独配低卡组合）
—— 有异议直接说，没意见我就按这个算价下单。
```

## 2. 异议分类与响应

| 级别 | 特征 | 响应方式 |
|---|---|---|
| **L0** | 过敏、宗教禁忌、素食 | **立即替换，不讨价还价**。改完主动说明"因为 X 是硬忌口，已把 Y 换成 Z" |
| **L1** | 不吃辣、控热量、不喝碳酸 | 必须满足。换不了要明说原因，并给出最近似的替代 |
| **L2** | 想加份、想换某单品 | 报价式回应，决策权交发起人 |

L2 报价式回应模板：

> 加一份麦辣鸡翅要 +¥12，总价 ¥158，超预算 ¥8。
> 砍掉 1 份大薯（−¥9）可以抵消，要这么调吗？

关键是**永远给出代价和抵消方案**，而不是"超预算了不行"。

## 3. 冲突矩阵

### 3.1 有人不吃辣 + 有人要辣

- 主餐统一不辣（保住 L1）
- 辣味做成**共享池单品**（麦辣鸡翅 / 辣翅），要辣的人自取
- 或辣味酱包**另附**，不预先拌入
- 话术：「主餐全部按不辣配，辣鸡翅放共享区，想吃辣的自己拿」

### 3.2 有人控热量 + 别人不控

- 分人配额：控热量者单独搭配，其他人走常规档
- 热量在确认卡上**标注到人头**，而不是只给平均值（平均值会掩盖个体差异）
- 不要为了统一而让所有人陪着吃低卡——那是另一种协调失败

### 3.3 预算不够

三级降级（每级都告知砍了什么）：

1. 砍随单购 / 加购 / 非必需小食
2. 饮料降档（大杯→中杯、可乐→免费水）
3. 主食降档，或减少共享池份数

**顺序原则**：先砍共享池，再砍饮料，最后才动主食。保住"每个人都有份"的公平感，比保住丰富度重要。

### 3.4 有人要双份 / 有人不吃主食

- 个人配额可转让：某人不吃主食 → 他的主食配额转入共享池
- 要双份的人：从共享池预算里出，不挤占他人配额
- 明确说出来：「A 不吃主食，他的主食额度换成了 1 份麦乐鸡放共享区」

### 3.5 有人迟迟不回复

- 默认同意制兜底：提案发出后，以发起人设定的时间（默认立即）未表态即通过
- 不要无限等待；到第 3 轮还没收敛就请发起人拍板
- 话术：「还有 2 位没表态，按默认同意处理，现在要下单吗？」

### 3.6 素食者与麦当劳的现实

麦当劳素食选择有限（玉米杯、薯条、沙拉、部分时段素食堡）。**明确告知可选范围，不要硬凑**，更不要为了"满足"而推荐含肉单品。若门店确实无合适单品，直接说明并建议该成员单独解决。

## 4. 收敛失败的处理

超过 3 轮仍不收敛时，停止迭代，输出：

```
⚠️ 还有 2 项异议没达成一致
  ① B 想要麦辣鸡翅（+¥12，超预算）
  ② C 说不吃牛肉但没说清能否吃鸡
建议方案：按当前版本下单，麦辣鸡翅由 B 自付另加
请拍板：按建议下单 / 再改一版
```

把"未解决项 + 建议 + 二选一"摆出来，让发起人一次决策。**不要陷入第 4 轮。**

## 5. 沟通纪律

- 每轮提案 ≤ 15 行
- 硬约束满足情况**逐条打勾**展示，这是信任的来源
- 任何价格变化都要说明原因（换了这个 / 用了这张券 / 砍了那个）
- 不用"大家觉得呢"这种无法决策的问句，用「改 X 还是不改」的二选一
- 全程只用一次 `@全体` 式的提案广播，后续只回复提异议的人
