# 聚餐菜单搭配算法

## 1. 双池模型

多人点餐与单人点餐的本质区别：**有些东西该人手一份，有些东西该共享**。

| 池 | 内容 | 数量规则 |
|---|---|---|
| **个人池** | 主食（汉堡/卷/饭）、饮料 | 严格按人头 1 份 |
| **共享池** | 薯条、麦乐鸡、鸡翅、玉米杯、派等小食 | `ceil(人数 ÷ 2)` ~ `ceil(人数 × 0.7)` 份 |

为什么共享池不是人手一份：

- 聚餐场景小食的实际消耗量远低于人均 1 份，人手一份必然浪费
- 同样的钱，3 份不同小食共享，比 6 份同种小食体验更好
- 共享池是预算调节的**缓冲层**——超预算时先砍这里，不会动到"每个人都有份"的公平感

人数对应的共享池份数：

| 人数 | 共享小食份数 |
|---|---|
| 2–3 | 2 |
| 4–5 | 3 |
| 6–8 | 4–5 |
| 9–12 | 6–8 |

## 2. 配额计算

```
人均预算       = 总预算 ÷ 人数
个人池预算     = 人均预算 × 0.65 × 人数     # 主食 + 饮料占大头
共享池预算     = 总预算 − 个人池预算         # 约 35%
```

主食与饮料内部再分：主食 ≈ 个人池预算的 72%，饮料 ≈ 28%。

这套比例只是**初值**，最终必须让 `calculate-price` 说话。做法：

1. 按配额挑出候选组合
2. 调 `calculate-price` 试算
3. 差额超 ±8% 就调整档位再算一次
4. 最多迭代 3 次，取最接近预算且不超的方案

**严禁自行加总价格下结论**——门店定价、活动价、券后价只有算价接口知道。

## 3. 人均档位 → 结构映射

源自麦当劳团餐搭配规则，聚餐场景同样适用：

| 人均 | 结构 |
|---|---|
| < ¥20 | 主食基础款，或纯小食组合（宿舍夜宵常见） |
| ¥20–30 | 主食 + 小食 **或** 主食 + 饮料 |
| ¥30–40 | 主食 + 薯条/小食 + 饮料 |
| ¥40–50 | 主食 + 薯条 + 小食 + 饮料 |
| > ¥50 | 丰富组合，小食尽量不重复 |

办公室工作餐的典型区间是 ¥25–40/人；宿舍夜宵 ¥15–30/人；朋友聚会 ¥35–60/人。

## 4. 热量控制清单

先调 `list-nutrition-foods` 拿到真实营养数据，再按下表选品。

**控热量者的搭配原则**：

| 位置 | 常规选择 | 控热量替换 |
|---|---|---|
| 主食 | 巨无霸 / 双层牛肉堡 | 板烧鸡腿堡 / 麦香鱼 / 烤鸡类单品 |
| 小食 | 大薯 | 玉米杯 / 中小薯 / 沙拉（共享池里给他留一份低卡的） |
| 饮料 | 可乐（中/大） | 无糖可乐 / 零度 / 矿泉水（免费） |
| 加料 | 酱包全加 | 少酱或不要酱 |

**热量标注规则**：

- 确认卡上给出**人均热量**总览
- 控热量的人**单独标注**其个人热量
- 数据缺失的单品标注「热量未知」，不要编数字

参考量级（以 `list-nutrition-foods` 返回为准，此处仅为规划时的量级感知）：

- 单个汉堡：约 400–600 kcal
- 中薯：约 300–350 kcal
- 中杯可乐：约 150–200 kcal
- 麦乐鸡 5 块：约 220–280 kcal

控热量者一餐控制在 550–700 kcal 是现实目标，不要承诺"300 kcal 吃饱"。

## 5. 不吃辣的处理路径

1. **首选**：直接选不辣单品（板烧鸡腿堡、麦香鱼、吉士汉堡、原味鸡块等）
2. **次选**：`query-meal-detail` 查目标单品的 `modification`，看能否去掉辣味酱料
3. **兜底**：把辣味需求移到共享池（麦辣鸡翅单独一份），主餐全部不辣；或直接说明"该单品辣味无法去除，建议换 X"
4. **特调传参**：`modification.values[]` 的 key 规则——选中项用 `selectedKey`，未选中项若 `unselectedKey` 非空也**必须传**，少传会导致口味计算错误

**不要为了凑单让不吃辣的人"将就"**，这是 L1 约束。

## 6. 提案的呈现顺序

提案里按这个顺序排，最容易被快速扫读并给出异议：

1. 一行总览（人数 / 预算 / 场景）
2. 个人池（每人分到什么）
3. 共享池（大家分什么）
4. 硬约束满足情况（逐条打勾）
5. 热量与人均金额
6. 一句收敛指令（"有异议直接说，没意见就按这个下单"）

每轮提案控制在 15 行以内。太长没人看，协调成本反而上升。
