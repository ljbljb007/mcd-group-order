## 痛点：多人点麦当劳，最麻烦的不是选什么，是协调

一个人点麦当劳，30 秒搞定。六个人点麦当劳，会变成这样：

- 「你想吃什么？」「随便」「都行」——问了等于没问
- 有人不吃辣，有人非辣不吃——吵不出结果
- 有人要控热量，有人觉得管那么多干嘛
- 算完发现超预算 40 块，又得从头砍一轮
- 最后总有人临时改主意，前面白聊

**这些问题的共同点是：它们都不是"选餐"问题，是"协调"问题。**

`mcd-group-order` 就是专门解决协调环节的 Skill。它基于麦当劳官方 MCP，把「收集偏好 → 消解冲突 → 搭配菜单 → 领券用券 → 算价 → 统一下单」整条链路跑完。

---

## 核心机制

### 1. 提案先行 + 异议收敛（而不是逐个问偏好）

逐个问"你想吃什么"在多人场景必然失败：6 个人 × 3 轮 = 18 次往返，且答案互相冲突。

本 Skill 反过来做：**先给一份完整提案，再收异议，没反馈即默认通过。**

```
🍔 首版提案（6人 · ¥150）
个人池：巨无霸×3 / 麦香鱼×2 / 板烧鸡腿堡×1 + 可乐×6
共享池：大薯×2 / 麦乐鸡(5块)×3
硬约束：不吃辣 ✓ | 控热量 2人 ✓（已单独配低卡组合）
—— 有异议直接说，没意见我就按这个算价下单。
```

异议成为"相对于方案的偏差"，认知负担从"从零想吃什么"降到"这一条我同意吗"。

### 2. 双池配额：个人池 + 共享池

聚餐和单人点餐的本质区别是——有些东西该人手一份，有些东西该共享。

| 池 | 内容 | 数量 |
|---|---|---|
| 个人池 | 主食 + 饮料 | 严格按人头 1 份 |
| 共享池 | 薯条 / 麦乐鸡 / 鸡翅 / 玉米杯 | `ceil(人数÷2)` ~ `ceil(人数×0.7)` 份 |

同样预算下，共享池让小食种类更丰富、浪费更少，而且它天然是**预算缓冲层**——超预算时先砍共享池，不动"每个人都有份"的公平感。

### 3. 忌口分级：硬约束零妥协

| 级别 | 内容 | 处理 |
|---|---|---|
| **L0** | 过敏、宗教禁忌、素食 | 违反即方案作废，无条件替换 |
| **L1** | 不吃辣、控热量、不喝碳酸 | 必须满足，影响主食与饮料选择 |
| **L2** | 想加份、想换某单品 | 报价式回应，决策权交发起人 |

L2 的回应永远带代价：「加麦辣鸡翅 +¥12，超预算 ¥8，砍 1 份大薯（−¥9）可抵消，要吗？」

### 4. 冲突消解内置

| 冲突 | 解法 |
|---|---|
| 有人不吃辣 + 有人要辣 | 主餐统一不辣，辣味做成共享小食或辣酱另附 |
| 有人控热量 + 别人不控 | 分人配额 + 热量标注到人头（不给平均值掩盖差异） |
| 预算不够 | 三级降级：砍加购 → 饮料降档 → 主食降档 |
| 有人要双份 / 有人不吃主食 | 个人配额可转让，不挤占他人 |
| 迟迟不回复 | 默认同意制兜底，不无限等待 |

### 5. 真实 MCP 闭环，不是纸上谈兵

菜单、价格、优惠券、热量、订单全部来自麦当劳官方 MCP 实时接口。**方案里的东西一定点得到，报出来的价一定是真实券后价，最后真的能落成一单。**

## 使用示例

### 输入（一句话）

> 6 个人，预算 150 元，有人不吃辣，有人想控制热量，帮我们点一单。

### 过程

**① 立案确认**

```
📋 立案
6人 · 预算¥150（人均¥25）· 麦乐送到 张江xx路
硬约束：1人不吃辣 · 2人控热量
```

**② 首版提案**（AI 直接给，不问你每个人想吃什么）

```
🍔 首版提案（6人 · ¥150）
个人池：板烧鸡腿堡×2 / 麦香鱼×2 / 吉士汉堡×2 + 可乐×6（2人换无糖）
共享池：大薯×2 / 麦乐鸡(5块)×3 / 玉米杯×2
硬约束：不吃辣 ✓（全部单品不辣）| 控热量 ✓（2人已配低卡组合）
热量：人均约 760 kcal，控热量者约 590 kcal
```

**③ 异议收敛**（只处理提出来的偏差）

> 参与者 B：我想吃麦辣鸡翅。

```
加一份麦辣鸡翅 +¥12，总价 ¥158，超预算 ¥8。
砍掉 1 份大薯（−¥9）可以抵消。要这么调吗？
—— 顺带说明：鸡翅放共享区，不吃辣的同事不受影响。
```

**④ 用券 + 试算**（自动领券、选本单可用券、调真实算价接口）

```
🎟️ 帮你领了 3 张券，本单可用：满100减15
💰 试算：¥161.50 → 券后 ¥146.50（预算内，剩 ¥3.5）
```

**⑤ 确认卡 + 下单**

```
✅ 聚餐点单确认卡
━━━━━━━━━━━━━━━━━━━━━━
👥 6人 · 麦乐送 · 张江店
💰 预算 ¥150 → 实付 ¥146.50（人均 ¥24.4）
🎟️ 已用券：满100减15（省 ¥15）
🚫 硬约束：不吃辣 ✓ | 控热量 2人 ✓
🔥 热量：人均约 745 kcal（控热量者 A 620 / B 580）

【个人池】板烧鸡腿堡×2 / 麦香鱼×2 / 吉士汉堡×2 / 可乐×6（2杯无糖）
【共享池】大薯×1 / 麦乐鸡5块×3 / 玉米杯×2 / 麦辣鸡翅×1

💳 AA：每人 ¥24.4
━━━━━━━━━━━━━━━━━━━━━━
回复「确认下单」我就提交。
```

确认后 `create-order` 真实落单，返回支付链接；支付后自动核实订单状态。

> 完整对话样例见 [`examples/sample-session.md`](./examples/sample-session.md)。

## 安装

### 前置条件

1. 申请麦当劳中国 MCP Token：[mcd-mcp-server 使用指南](https://github.com/M-China/mcd-mcp-server)
2. 在客户端中配置 `mcd-mcp`（配置模板见 [`mcp-config.example.json`](./mcp-config.example.json)，替换 `${MCD_MCP_TOKEN}` 为你的 Token）

### 在 WorkBuddy 中使用（推荐）

1. 打开 WorkBuddy → 左侧边栏【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置 MCP】
2. 填入 `mcp-config.example.json` 的内容（记得替换 Token）并保存
3. 回到自定义连接器，把 `mcd-mcp` 启用
4. 安装 Skill：

```bash
# 用户级（所有项目可用）
cp -r mcd-group-order ~/.workbuddy/skills/

# 或项目级
cp -r mcd-group-order <项目根>/.workbuddy/skills/
```

5. 直接对话：`6个人，预算150元，有人不吃辣，帮我们点一单`

### 在其他支持 MCP 的客户端中使用

`SKILL.md` 是标准的 Agent Skill 格式（`name` + `description` frontmatter + Markdown 编排），可直接放入任意支持 Skill 机制的客户端的 skills 目录；`references/` 下的文件由 Agent 按需加载。

## 设计上的取舍

- **不拆单**。MCP 一次只能下一单，所以"统一下单"就是一张订单包含所有人，AA 是线下收款。
- **不无限收敛**。异议最多 3 轮，之后把未解决项 + 建议 + 二选一摆给发起人拍板。协调器的价值是缩短决策，不是替人决策。
- **不编造数字**。价格只认 `calculate-price`，热量只认 `list-nutrition-foods`，缺了就标「未知」。
- **下单前必确认**。`create-order` 是真实扣款动作，执行前必须复述订单并获明确肯定。
