# 完整对话样例：办公室 6 人工作餐

> 场景：周五中午，行政小李要帮 6 位同事订麦当劳，预算 150，其中 1 人不吃辣、2 人在控热量。
> 以下为真实流程还原，工具调用以「🔧」标注。

---

## 第 1 轮：用户开口

**小李**：6 个人，预算 150 元，有人不吃辣，有人想控制热量，帮我们点一单。

**AI**：

```
📋 立案
6人 · 预算¥150（人均¥25）· 麦乐送到 张江镇xx路 3 号楼
硬约束：1人不吃辣 · 2人控热量

两件事确认一下：
1. 控热量的两位大概想控制在多少？我按每人 600 kcal 以内配可以吗？
2. 饮料统一可乐，还是让大家自选中杯/无糖？
```

> 只补问了两个真正影响方案的项，没有问「每个人想吃什么」。

## 第 2 轮：用户补充

**小李**：600 以内就行。饮料一半无糖吧，另外 B 说他想吃麦辣鸡翅。

**AI**：

🔧 `delivery-query-addresses` → 取到地址「张江镇xx路 3 号楼」`addressId`
🔧 `delivery-query-stores(addressId, beType=2)` → 取到门店 `storeCode` + `beCode`
🔧 `query-meals(storeCode, orderType=2, beType=2, beCode)` → 在售菜单与价格
🔧 `list-nutrition-foods()` → 热量数据

```
🍔 首版提案（6人 · ¥150 · 人均¥25）

【个人池】
  板烧鸡腿堡  ×2   约 480 kcal / 份
  麦香鱼      ×2   约 400 kcal / 份
  吉士汉堡    ×2   约 300 kcal / 份
  可乐        ×3
  无糖可乐    ×3

【共享池】
  大薯        ×2
  麦乐鸡(5块) ×3
  玉米杯      ×2

🚫 硬约束
  不吃辣 ✓（全部主餐不辣，辣味单独处理）
  控热量 ✓（A：麦香鱼+玉米杯 ≈ 520 kcal；B：吉士汉堡+玉米杯 ≈ 480 kcal）

💰 预估 ¥158（未用券）—— 略超，下一步我领券再算一次
```

## 第 3 轮：异议

**小李**：A 说麦香鱼太腥，能不能换？

**AI**：

```
可以。麦香鱼 → 板烧鸡腿堡，热量 400 → 480，仍在 600 以内。
差价 +¥4，总价 ¥162。

另外 B 要的麦辣鸡翅 +¥12，砍掉 1 份大薯（−¥9）可抵消大部分。
两个都改的话：¥162 + 12 − 9 = ¥165，还没用券。

先按这个组合去算真实价格，券后大概率能回到 150 以内。
```

🔧 `auto-bind-coupons()` → 自动领到 3 张券
🔧 `query-store-coupons(orderType=2, beType=2, storeCode, beCode)` → 本单可用：满 100 减 15

## 第 4 轮：算价

🔧 `calculate-price(...)` → 返回 `16150`（分）

```
🎟️ 帮你领了 3 张券，这单能用「满100减15」

💰 试算结果
  原价  ¥161.50
  券后  ¥146.50
  预算  ¥150.00  → ✅ 预算内，剩 ¥3.50，人均 ¥24.4

要不要把剩的 ¥3.5 加一份玉米杯放共享区？不加也行。
```

**小李**：不加了，就这个。

## 第 5 轮：确认卡

**AI**：

```
✅ 聚餐点单确认卡
━━━━━━━━━━━━━━━━━━━━━━━━━━━
👥 6人 · 麦乐送 · 张江店
💰 预算 ¥150 → 实付 ¥146.50（人均 ¥24.4）
🎟️ 已用券：满100减15（省 ¥15）
🚫 硬约束：不吃辣 ✓ | 控热量 2人 ✓
🔥 热量：人均约 745 kcal
       控热量者 A ≈ 560 kcal / B ≈ 520 kcal

【个人池】
  板烧鸡腿堡 ×3（含 A 由麦香鱼改）
  吉士汉堡   ×2
  麦香鱼     ×1
  可乐       ×3 / 无糖可乐 ×3
【共享池】
  大薯        ×1
  麦乐鸡 5块  ×3
  玉米杯      ×2
  麦辣鸡翅    ×1（B 要的，放共享区，不吃辣的同事不受影响）

🥤 餐具：需要（已勾选，6 份）
💳 AA：每人 ¥24.4
━━━━━━━━━━━━━━━━━━━━━━━━━━━
回复「确认下单」我就提交；要改直接说改哪。
```

## 第 6 轮：下单

**小李**：确认下单。

🔧 `create-order(storeCode, orderType=2, beType=2, beCode, addressId, items, couponId, needTableware=true, remark="放前台，电话联系")`

**AI**：

```
✅ 订单已创建：MCD20261023xxxx

💳 支付链接：https://……
（或打开麦当劳 APP 在「我的订单」中完成支付）

支付完成后回复「支付完成」，我帮你确认订单状态。
```

## 第 7 轮：收尾

**小李**：支付完成。

🔧 `query-order(orderId)` → 已支付，制作中

**AI**：

```
✅ 已确认：订单支付成功，门店制作中，预计 25 分钟送达。

📌 给群里转发用：
6 人份 · 实付 ¥146.5 · 人均 ¥24.4
主餐：板烧×3 / 吉士×2 / 麦香鱼×1
共享：大薯×1 / 麦乐鸡×3 / 玉米杯×2 / 辣翅×1（辣的单独放）
不吃辣的同事吃主餐没问题，辣翅在共享区自己拿。
```

---

## 这个流程里省掉了什么

| 常规做法 | 本 Skill |
|---|---|
| 群里问 6 遍「你想吃什么」 | 0 次，直接给提案 |
| 反复改菜单到超预算再砍 | 超预算时给三级降级路径 + 代价报价 |
| 手动查券、手动算总价 | 自动领券 + 真实算价接口 |
| 有人忌口就推倒重来 | 硬约束优先替换，其余不动 |
| 口头统计 AA 金额 | 确认卡直接给出人均 |
